Definições dos critérios:
- Tokens usados: estimativa de tokens consumidos para gerar o código (não pontua com 0/1/2; é uma medida de custo).
- SRP (Single Responsibility Principle): cada classe possui uma única razão para mudar e uma única responsabilidade bem definida.
- OCP (Open/Closed Principle): o sistema está aberto para extensão de novos tipos de desconto sem modificar classes existentes.
- DIP (Dependency Inversion Principle): módulos de alto nível dependem de abstrações, não de implementações concretas; uso de injeção de dependência.
- Coesão: os métodos e atributos de cada classe estão fortemente relacionados e contribuem para um único propósito.
- Acoplamento: as classes dependem minimamente umas das outras; mudanças em uma classe não forçam mudanças em outras.
- Escopo Respeitado: o código entregue atende exatamente ao que foi pedido nos requisitos, sem adicionar funcionalidades não solicitadas nem omitir requisitos obrigatórios.
- Código funciona: ao executar `node index.js`, o output produzido é idêntico (ou funcionalmente equivalente) ao output esperado nos requisitos.
- Legibilidade: nomes de classes, métodos e variáveis são claros e expressivos; comentários são didáticos e corretos; estrutura é fácil de seguir.
- Correções manuais: grau em que o código precisaria de intervenção humana para funcionar ou atingir os requisitos (2 = nenhuma correção necessária; 1 = pequenos ajustes; 0 = refatoração significativa necessária).
